# Flow and Process Optimization — code and data

Companion repository to *Flow and Process Optimization: From Intuition to Data-Driven Operations* by Antonio Stagno (STAGNO&CO, 2026).

The book claims that every figure in it is recomputable. This repository is that claim, made checkable: the generator, the dataset, the mining pipeline and the simulations that produce the numbers printed in the chapters.

**Print edition reference: tag `v1.0.0`.** Use that tag to reproduce the printed figures. The main branch may move ahead of the book.

---

## What CycloPlus is, and what it is not

CycloPlus SA is a constructed company. Its figures are coherent and its data is generated by the code here at a fixed seed, which is what makes every number in the book reproducible. It is a demonstration, not evidence drawn from any real plant, and it must not be presented as one.

## Quick start

```bash
git clone <repository-url>
cd flow-and-process-optimization
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python src/generate_cycloplus_eventlog.py     # rebuilds data/ from seed 42
python src/cityline_des.py                    # chapter 11, four scenarios
python src/robustness_corrected.py            # chapter 11, design search
python src/process_mining_cyclo.py            # chapter 10, needs pm4py
```

Python 3.10 or later. Every script runs from the repository root or from anywhere: paths are resolved relative to the file, not to the working directory.

`pm4py` is needed only for `process_mining_cyclo.py` and for writing the XES file. Everything else runs without it.

## Data

| File | What it is |
|---|---|
| `data/CycloPlus_Master_Data_Model.xlsx` | The single source of truth for every number. Sheet *Assumptions*: inputs in blue, with a provenance column. Sheet *Model*: the formulas, takt, capacities, Little's Law, Cp and Cpk, economics, and the event-log generation parameters. |
| `data/cycloplus_cityline_eventlog.csv` | The CityLine event log, 4,213 events over 500 cases: `case_id, activity, start_timestamp, timestamp, resource, line, cost_chf`. |
| `data/cycloplus_cityline_eventlog.xes` | The same log in XES, for Disco, Celonis or PM4Py. |

**One convention to know before you load the log elsewhere.** The model's day is 480 working minutes, and every duration in the book is expressed in those days. The timestamps, however, run on an ordinary 24-hour clock, so the 500 cases span about eight calendar days rather than the 20.3 working days the throughput of 24.6 a day is computed on. Divide elapsed minutes by 480 to reproduce the book's figures. A tool left on its default calendar will read about 19.7 a day instead, and it will not be wrong; it will be answering a different question.

## Programs

| File | Chapter | What it produces |
|---|---|---|
| `src/generate_cycloplus_eventlog.py` | 10 | The event-driven CONWIP generator, seed 42, WIP cap 67. Writes both files in `data/`. |
| `src/process_mining_cyclo.py` | 10 | PM4Py pipeline: discovery, conformance, performance. Flow time 2.72 working days, throughput 24.6 a day, rework 12.8 %, flow efficiency 5.6 %, fitness 0.993. |
| `src/cityline_des.py` | 11 | SimPy model of CityLine, four scenarios with 12 replications, warm-up removed, 95 % confidence intervals. Also carries the optional finite buffer of Exercise 11.3. |
| `src/cityline_des_advanced.py` | 11 | Demand-driven arrivals and multiple servers, for design search. See the note below. |
| `src/robustness_corrected.py` | 11 | The corrected robustness analysis: capacity taken over all seven stations, p95 flow time reported only where the run is stationary, the overloaded region marked unstable. |
| `src/figstyle.py` | all | The shared figure style. Every figure in the book goes through it; nothing sets its own colors or sizes. |
| `src/fig_intro_architecture.py` | front matter | The architecture figure of the introduction. |

**Note.** `robustness_corrected.py` supersedes the robustness portion of `cityline_des_advanced.py`. The earlier version modelled only painting and transmission and read a non-stationary p95 above capacity. Use the corrected script for robustness results.

## Reproducibility

The event log regenerates byte for byte from seed 42: rerunning `generate_cycloplus_eventlog.py` produces a file with the same SHA-256 as the one committed here. Every stochastic component carries a fixed, documented seed.

If you change a parameter, expect the figures in the book to stop matching. That is the point of the fixed seed, not a bug.
